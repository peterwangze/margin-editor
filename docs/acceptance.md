# Margin 发行验收清单

每次发行以候选标签及提交为单位复制运行记录。记录系统版本、架构、安装包哈希、执行人或 CI、实际输出与缺陷链接。状态使用 `通过`、`失败`、`未验证`、`未实现`。合并新功能或修复时新增用例或更新既有步骤，保留 ID。回归测试在独立用户目录和临时文件夹执行。

## 正式版发布门槛

正式版验收以 [纯文本任务和兼容边界](research.md) 为准。每个架构提交静态包检查和打包后实际交互证据。只有下表全通过，且所验构建与发布标签指向同一提交，才发布正式版。已有 GitHub 预发行继续保留历史记录。

| ID | 必须执行的验收 | 通过条件 |
| --- | --- | --- |
| G01 | 静态：检查 Windows、macOS、Linux 的 x64 和 ARM64 包及包内运行时；核对产品版本、处理器、包类型、签名状态和许可证 | 每个系统两种架构、每架构两种下载形式；证据关联 SHA-256，安装说明如实写明系统依赖和签名状态 |
| G02 | 静态：从发行包启动后检查 1024×720 和 650×540 的菜单、工具栏、文档标签、编辑区、状态和窄窗布局；保留截图，检查可见标签、溢出和键盘焦点 | 元素按阅读顺序呈现，打开文档可见，菜单能用键盘操作；控制台无页面异常 |
| G03 | 实际交互：从对应平台发行包打开本地文件，输入 Unicode，查找替换，检查隐藏字符、预览并应用清理，撤销/重做，保存再核对 CRLF 与 UTF-8 原始字节 | 两种包形式都能启动并通过，交互不需要服务或账号；Windows 验证 Setup 安装及卸载，macOS 使用 DMG 和 ZIP 中复制出的应用，Linux 验证 DEB 以及 AppImage |
| G04 | 实际交互：运行目标系统桌面回归，覆盖保存、编码与 BOM、磁盘冲突、草稿恢复、目录范围和选择性替换、大文件跨页查找和保存 | 除正向结果外，取消关闭、检测到外部修改等保护场景也通过，文件字节正确 |
| G05 | 核对正式 GitHub Release、下载链接、SHA-256 与仓库 About | 发布的 12 个文件与验收工件完全一致，Release 为正式版且为 Latest |

没有在宿主机上验证的辅助技术、系统策略或文件关联，列入补验记录。自动化插入中文不等同于验证操作系统 IME；无发布者证书和未公证的包按发行页说明安装。

## Notepad++ 迁移范围与补验

F01–F12 是早期迁移对照，保留子项和历史结果。当前产品承诺与实际用例见 G01–G05。以下项目没有通过原版等价验收，仍保留在兼容范围或补验清单中：

- Windows DLL/Scintilla 互操作、插件目录和安装管理，Windows Shell 注册、完整 Notepad++ CLI 和安装器参数。
- Boost.Regex 1.92 已接入。依赖原始 CRLF 的表达式、区域设置和完整差分语料仍待验收。完整书签/标记样式、项目编辑及导出、主题 XML 和函数规则导入仍待实现。已迁移常见会话、偏好字段、菜单快捷键和项目 XML 的树与文件路径。原版宏与插件快捷键仍待迁移。
- UDL 的嵌套、行延续、多词匹配及全部样式规则，完整代码页和内建 lexer 清单，参数提示和函数补全定义迁移。
- 原版编辑和设置菜单中的长尾能力，包括虚拟空间列粘贴、完整宏动作、GUI 本地化、自定义菜单/工具栏，以及 Windows 专有的鬼打字和系统集成。
- 大文件全局正则替换、部分多字节旧编码的分页写入、全部平台及架构的离线人工安装、IME、屏幕阅读器、高对比度和签名验证。

安装包的 CI 通过表示已生成工件，带 Smoke 步骤的架构还验证了包内应用的真实编辑与磁盘操作。完整安装程序、系统文件关联和卸载用例需要独立证据。
